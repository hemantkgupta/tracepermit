# A readiness packet is not a go decision

A source commit, archive hash and copied checklist answer different questions.
The commit identifies source; the hash identifies bytes; the checklist names
observations still needed. None identifies an authenticated operator, proves a
network deny or grants permission to run a workload.

An EKS campaign needs a reviewed release, selected private inputs, a named
operator, independent evidence and a stop procedure before its first effect.
Keep a NOT_RUN row when evidence is absent. Record an actual failure rather
than interpreting an unreachable control as containment. Refresh an observation
when needed, not merely its timestamp.

Quarantine protects later admissions after an acknowledged control change.
Already-started work needs terminal-or-unknown accounting and read-only
reconciliation; ending a process is not rollback. An unknown record must remain
unknown without a reconstructed permit or resend.

The [readiness packet](../planning/eks-p1-rehearsal-readiness.md) organizes that
review. The existing acceptance kit can report REVIEW_REQUIRED or BLOCKED.
The named humans still own the exact go/no-go decision and its limits.
